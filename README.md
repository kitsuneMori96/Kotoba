# Kotoba

面向 Galgame 汉化的本地翻译质量工作台。重点关注人物译名一致性、带证据的人称指代裁决和可追溯的人工审校。

> 当前为基础原型：支持结构化 JSON 剧本的人工翻译与规则检查，尚不支持自动翻译、真实游戏引擎脚本提取或可直接安装的汉化补丁生成。规则通过不代表语义、性别指代或剧情信息一定正确。

## 快速开始

需要 Node.js 24 或更高版本。项目使用 Node 内置 HTTP、SQLite 和测试模块，无第三方运行依赖，无需先执行 `npm install`。

```sh
npm start
```

在浏览器打开 <http://127.0.0.1:4173>。请使用这个地址而非 `localhost`，服务会校验 Host 和来源，仅监听本机回环地址；不适合直接部署到公网。

首次打开可点击「载入演示」，查看故意设置的译名错误、未决指代及控制码丢失。

```sh
npm test
```

测试覆盖质量规则、HTTP 导入与导出门禁、并发修订保护、人物修改后的关联重审，以及 SQLite 重启持久化。集成测试临时使用端口 4179，数据库写入系统临时目录并在测试后清理。

## 当前功能

- **剧本审校**：按路线筛选；展示同路线、同场景内相邻句上下文；编辑译文并保存草稿。
- **人物档案**：使用稳定实体 ID，维护标准译名、原文别名和默认代词。
- **逐处裁决**：为已标注的姓名或指代绑定人物，填写允许表达及人工裁决证据。
- **规则检查**：检查空译文、常见控制码内容与顺序、未确认提及、缺失证据和预期表达。
- **人工确认**：存在本句规则问题时不能确认审核；全稿无问题后才能导出审核稿。
- **关联重审**：人物资料发生变化后，以该人物为说话人或已绑定该人物的句子重新进入待审。
- **修订记录**：保存完整项目快照，界面展示最近 50 条修订；旧版本不会因导入而删除。
- **本地保存**：SQLite 持久化，基于修订号拒绝过期写入。

人物默认代词不会自动覆盖每处表达，也不会根据姓名、立绘或日语第一人称猜测性别。原文含糊时，应根据当前剧情提供证据，或在适当情况下保留「那个人」等中性表达。

## 基本工作流

1. 载入演示，或导入符合下述格式的 JSON 文件（文件上限 2 MB，整个请求体也有 2 MB 上限）。
2. 核对人物标准译名和别名。
3. 逐句编辑译文，核对已标注提及的实体、允许表达及证据。
4. 保存草稿，处理规则问题，然后点击「确认审核」。
5. 全部句子审核完成后，点击「导出审核稿」下载 `kotoba-reviewed.json`。

导入或重新载入演示会替换当前工作稿，但历史版本保留；导入的所有句子都会重新进入待审。请在切换句子、筛选或页面前保存修改，当前没有未保存编辑保护。当前也没有历史版本回滚界面。

## 剧本 JSON 格式

最小示例：

```json
{
  "name": "示例项目",
  "characters": [
    {
      "id": "aki",
      "name": "秋",
      "aliases": ["アキ"],
      "pronoun": "未知"
    }
  ],
  "lines": [
    {
      "id": "common-001",
      "route": "共通线",
      "scene": "车站",
      "speaker": "",
      "source": "アキはまだ来ていない。[wait]",
      "target": "秋还没来。[wait]",
      "reviewed": false,
      "mentions": [
        {
          "id": "m1",
          "source": "アキ",
          "kind": "name",
          "entity": "aki",
          "resolved": true,
          "evidence": "原文明确提及アキ，与项目人物表对应。",
          "expected": ""
        }
      ]
    }
  ]
}
```

### 字段约定

- 人物 `id` 全项目唯一；句子 `id` 全项目唯一；提及 `id` 在本句内唯一。
- `characters[].pronoun` 为 `他`、`她`、`它` 或 `未知`。
- `lines` 非空，数组顺序作为剧本顺序；`speaker` 是人物 ID，旁白或未知说话人使用空字符串。
- `route`、`scene` 为字符串，用于筛选与上下文分组，不等于可执行分支条件。
- `mentions` 可以为空，但这意味着该句没有显式标注的实体检查。
- 提及 `source` 必须是本句原文中的非空子串；`kind` 为 `name` 或 `pronoun`。
- `entity` 为已有的人物 ID；未知时使用 `null`，同时 `resolved` 必须为 `false`。
- `resolved: true` 的提及仍需填写非空 `evidence` 才能通过审校。
- 姓名提及的 `expected` 留空时，使用绑定人物的标准译名；填写后可表示本句采用的昵称、姓氏或称号。
- 指代提及必须显式填写 `expected`，不从人物默认代词推导；当前不支持以空字符串表示省略。

人物与提及定义需要预先在导入文件中准备：界面可修改已有的人物资料和提及裁决，但尚不能新增人物或提及，原文提及的 ID、片段和类型也不能通过句子编辑接口改写。

## 数据与配置

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `4173` | 本地 HTTP 服务端口 |
| `KOTOBA_DATA_DIR` | 项目根目录下的 `data` | SQLite 数据目录 |

PowerShell 示例：

```powershell
$env:PORT = "4180"
$env:KOTOBA_DATA_DIR = "D:\KotobaData"
npm start
```

默认数据库为 `data/kotoba.sqlite`，采用 WAL 模式。备份前应停止实际 Node 服务进程，并保留数据库及仍存在的 `-wal`、`-shm` 伴随文件，或使用 SQLite 的一致性备份工具；不要在运行时仅复制主数据库文件。

本地数据库、环境文件、日志和依赖目录已加入 Git 忽略规则。不要将真实游戏剧本、个人翻译项目或 API 密钥提交到公开仓库。

```text
public/
  index.html      工作台页面

test/
  quality.test.js 规则回归测试
  server.test.js  HTTP 与持久化集成测试
```

## 已知边界与后续方向

- **实体检查依赖预标注**：别名列表当前只维护数据，不自动识别人物；未标注的提及不会被发现。
- **表达检查为子串检查**：尚无词边界、出现次数或译文区间对齐，不能据此证明每一处名字与代词都正确。
- **控制码检查为通用启发式**：识别方括号、花括号、部分格式化占位符和转义符，不是任何特定引擎的完整语法解析器。
- **上下文仅按路线与场景分组**：尚未实现条件分支图、时间线、人物知识状态、身份揭露范围或跨路线事实隔离推理。
- **证据由人工负责**：系统检查是否填写，不验证证据是否真实或足以支持裁决。
- **单工作稿、本机单用户**：没有账户权限、多项目管理、多人协作、自动翻译提供商或语义审校模型。
- **导出是审核 JSON**：后续需要实现引擎适配、原始字节与控制结构保留、补丁回写和游戏内验证。

后续优先推进结构化实体与剧情事实、可替换翻译模型、带证据的语义审校及真实引擎适配，避免将一个未经上下文约束的模型输出直接当作最终补丁。
